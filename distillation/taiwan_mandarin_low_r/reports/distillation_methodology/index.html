台灣溫柔女生 TTS 蒸餾做法與原理

這份報告說明：什麼叫 TTS 蒸餾、我們這次怎麼從 Qwen3 老師蒸餾到 ZipVoice-Distill、目前結果到哪裡，以及下一步怎麼把它變成可放手機的版本。

目前狀態

第一輪完整鏈路已完成

已經跑過 Qwen teacher corpus → ZipVoice fine-tune → ZipVoice-Distill → ONNX int8。這算第一版完整蒸餾鏈路，但還不是產品級完成。

先定義清楚

「完整蒸餾」不是手機 demo 能播就算。完整蒸餾的最低標準是：推論時不載入 Qwen3 teacher，也不靠 teacher reference audio；學生模型自己的權重已經學到目標聲音。

一、蒸餾的核心原理

Teacher / Student

用大模型教小模型

老師模型負責產生或定義目標聲音。學生模型負責學會相同聲音與語調，但要更小、更快、能部署。

Teacher
Qwen3 1.7B VoiceDesign，目標台灣溫柔女生聲音來源。
Student
ZipVoice / ZipVoice-Distill，目標是變成手機可用的 ONNX/int8 TTS。
TTS 跟 LLM 不一樣

不是只學文字答案，而是學聲音軌跡

TTS 蒸餾要學的是文字到語音的映射，包括音色、發音、停頓、音高、能量、語速、尾音。輸出不是 token，而是 acoustic features 或 waveform。

所以評估不能只看 loss。loss 下降代表模型更會模仿資料，但最終仍要聽：像不像台灣女生、會不會主播腔、是否漏字。
兩層蒸餾

先學聲音，再學快速生成

這條路線分成兩層：第一層讓 ZipVoice 吸收 teacher 聲線；第二層把生成步數壓低，讓推論更快。

1. Teacher 產生語料

Qwen3 生成台灣低卷舌、溫柔女生風格語音。

二、為什麼早期要平一點

台灣日常女生聲線通常不需要大起大落的舞台腔。早期訓練偏平，可以先壓住過度誇張的普通話 TTS 抑揚，讓學生學到穩、柔、低卷舌的底色。

Phase 1 平穩核心 300 句

平均 flatness 12.52，F0 range 22.06 st。用途是 warmup，先學穩定台灣感。

Phase 2 自然尾音 197 句

平均 flatness 13.31，F0 range 23.23 st。用途是後期加回句尾自然起伏，避免變成機器人。

風險

不能一路追求越平越好。台灣感不是單調，而是低戲劇性、尾音自然、停頓像聊天。過度平坦會犧牲情緒與可懂度。

四、目前數字

Qwen3 1.7B teacher 約 2.2GB

peak RSS 約 2.20-2.33GB。聲音目標強，但不適合一般手機離線部署。

ZipVoice-Distill ONNX int8 約 177MB

Python ONNX CPU 測試 peak RSS 約 1.21-1.22GB。這是目前手機候選模型包。

3-step 候選 RTF 0.1505

live preload 約 0.97s/句。速度很好，但要聽是否漏字或咬字糊。

4-step 候選 RTF 0.1990

live preload 約 1.25s/句。比 3-step 保守，可能更適合 demo 預設。

目前可說已完成什麼

已完成第一輪真蒸餾鏈路：teacher data 進入學生訓練，產出學生 checkpoint，再匯出 ONNX int8。這不是 reference-prompt demo。

目前還沒完成什麼

  • 還沒有在真手機上量測 peak memory、冷啟動、連續生成。
  • Python ONNX 測到 1.21GB RSS，不等於手機 native runtime 實際值。
  • 3-step / 4-step 還需要聽感選擇，不能只看 RTF。
  • 模型包約 177MB，若要更小，需要壓 vocoder 或換更小架構。

五、為什麼模型還是 177MB

ZipVoice-Distill 壓的是生成步數與推論成本，不一定會大幅縮小參數量。現在大頭是 FM decoder 119MB 與 vocoder 52MB。

調低 steps 會變快，但不會變小。要變小，需要模型結構壓縮。
可能縮小方向
  • 換更小 vocoder，因為目前 vocoder 52MB。
  • decoder pruning 或 low-rank compression。
  • 針對單一台灣女聲訓練更小 student。
  • 再做更激進量化，但要防止音質破壞。

六、下一步建議

1. 聽感選 checkpoint

先在 3-step / 4-step / 6-step 之間選一個預設。標準是：不漏字、尾音自然、不主播腔。

2. 真手機跑 native runtime

不要只看 Mac Python。要在 iOS/Android 上量冷啟動、peak memory、第一句生成、連續生成。

3. 第二輪資料擴充

加入數字、英文、產品 UI、長句、問句。現在資料偏 voice shaping，不足以覆蓋產品輸入。

4. 小型化實驗

若 177MB 可接受，先做 app；若不接受，就開 vocoder/decoder 壓縮分支，不要把 steps 當成 size optimization。
