一句話結論

目前真的能往手機即時前進的是 Piper/VITS：ONNX 約 60.4 MB，載入約 0.318s，Python ONNX CPU 三句推論約 0.099s / 句，peak RSS 約 511 MB。這個速度非常好，但它的自然度與音色上限比較低，接下來要靠你聽樣本判斷值不值得繼續大練。

Matcha 速度也不差，但部署包比較麻煩：acoustic checkpoint 208.7 MB + HiFi-GAN 53.2 MB，Python CPU peak RSS 約 1.53 GB。它是非 AR / flow-matching acoustic model，比 Piper 更有自然度潛力，但目前還不是手機-ready，必須做 ONNX/CoreML/NCNN 類匯出、vocoder 量化或換更小 vocoder。

整體流程圖

1. 選聲音
從下載資料夾女聲片段裁 reference，排除男聲、配樂、唱歌。你最後偏好的方向是台灣女生、溫柔、清亮、低卷舌。
→
2. 產老師語料
用 IndexTTS2 clone reference，生成 500 句日常對話。每筆資料有 text、teacher wav、reference metadata。
→
3. 轉學生格式
Piper 轉 phoneme ids；Matcha 轉 tone-number pinyin 並計算 mel mean/std。兩邊都做 train/valid split。
→
4. 長訓學生
Piper 從 v6 1,750 step resume 到 10,000 step；Matcha 從 last checkpoint resume 到 max_steps=10,000。

這算蒸餾嗎？

算 data distillation / teacher-student voice distillation。老師模型 IndexTTS2 先產生高品質 synthetic labels，也就是 500 句「文字 → 老師聲音 wav」。學生模型 Piper / Matcha 不直接看原始 reference，也不呼叫 IndexTTS2，而是學這批老師 wav 的音色、口音、語尾與節奏。

但它還不是 logits distillation。我們目前沒有拿 teacher 的 hidden states、token probabilities、duration posterior 或 mel distribution 做 KL / feature matching。TTS 開源模型之間架構差太多，這類蒸餾通常要改訓練 loop。現階段是實務上最直接的「資料蒸餾 + 單聲音 fine-tune」。

模型細節

Piper / VITS

Piper 的核心是 VITS 類模型：text/phoneme encoder、duration/alignment、flow、decoder/generator，訓練時搭配 discriminator 做 adversarial loss。它的優點是部署簡單，ONNX generator 可以直接在手機跑；缺點是單聲音 fine-tune 要把音色、韻律、情緒都壓進相對小的模型，品質上限通常不如大 clone 模型。

本輪訓練 checkpoint 很大，主要因為 Lightning checkpoint 包了 generator、discriminator、optimizer states；真正部署只需要 ONNX。

Matcha + HiFi-GAN

Matcha 是 conditional flow matching acoustic model：文字條件進 encoder，decoder 透過 ODE steps 生成 mel，再由 HiFi-GAN vocoder 轉 waveform。它是非 AR，理論上速度比大 AR/LLM TTS 好；但手機部署不是一個檔案，要處理 acoustic model + vocoder 的匯出、量化與記憶體。

這輪為了避開 espeak，使用 pinyin char frontend。這讓工程可控，但語音自然度可能被「字母級拼音」限制。

目前限制與下一步

問題原因下一步
Piper 速度很好，但可能不像 / 不自然 VITS 小模型壓縮太重；500 句 synthetic teacher 也可能不足以穩住韻律。 先人工聽本報告三句。若文字正確但音色不足，做 2k–5k 句 teacher corpus + speaker embedding/feature loss；若文字錯或雜訊，先檢查 phoneme frontend 與資料品質。
Matcha peak RSS 太高 Python + PyTorch + acoustic + HiFi-GAN 都在記憶體裡；手機不能照這條 runtime。 匯出 acoustic ONNX / CoreML，vocoder 換小 HiFi-GAN、MelGAN、BigVGAN tiny 或 EnCodec 類；再量化。
這還不是最嚴格的 logits distillation IndexTTS2、Piper、Matcha 架構不同，直接蒸 hidden/logits 要改各模型 training loop。 若你要真正研究型蒸餾，下一階段做 mel-level loss + speaker embedding loss + ASR text consistency loss，比單純訓 wav 更穩。
Teacher generation time 不列 目前 teacher manifest 的 seconds 欄位不可信；它看起來像錯誤紀錄，不是生成時間也不是音檔長度。 如果要完整 benchmark teacher，需要重新跑 IndexTTS2 三句並用同一支 profiler 記錄 load/gen/RSS。
