實測

路線模型/前端結果判斷
Piper pinyin + g2pW 同一個 60MB ONNX，文字先進 g2pW phonemize 7-10s / sentence；audio-only 約 0.08s 不適合手機即時，除非預熱且可接受慢前端。
Piper phoneme-id fast frontend, step100 pypinyin -> Piper Chinese phoneme ids -> ONNX 0.074s 產 2.89s audio；0.101s 產 4.44s audio 速度達標，是手機主線。
Piper phoneme-id fast frontend, step1000 same fast frontend, continued from step100 to max_steps=1000 load 0.298s；0.110s 產 4.55s audio；0.147s 產 6.18s audio；RTF 0.024 速度仍達標；這是目前的小模型基準版。
品質狀態 500 teacher wavs, continued to 1000 training steps deployable ONNX checkpoint，不是 final voice 下一步要更長訓練、更多自然語料、台灣讀音前端、再量化。

手機部署候選

候選大小Mac ONNX Runtime 結果判斷
FP32 step1000 60.4MB load 0.298s；RTF 0.024 目前穩定 mobile baseline。
Dynamic QInt8, all supported ops 18.4MB 載入失敗：current ORT CPU lacks ConvInteger kernel 暫不採用；需要 target EP 驗證或改量化策略。
MatMul/Gemm QInt8 only 60.8MB 可合成；load 0.279s；RTF 0.020-0.024 可跑但沒壓小，不是有效手機包。
FP16 31.0MB 載入後推理失敗：runtime Reshape error 不作為通用 ORT CPU 包；可留給 CoreML/NNAPI 專測。
Static QDQ INT8 n/a 量化階段失敗：ORT Softmax calibration range bug 暫不採用；需要圖簡化或目標平台量化工具。
