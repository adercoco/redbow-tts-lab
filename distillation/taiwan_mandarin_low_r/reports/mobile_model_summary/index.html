最後候選排序

1

Sherpa-ONNX ZipVoice int8

新的主線：先做手機 runtime

舊 baseline 裡聲學 proxy 很高，跨 iOS/Android 路線成熟。接下來重點是把台灣女生 reference 固定、量實機 RSS/耗時、整理 app runtime。

模型大小約 180.7MB zh-min + vocoder；196.7MB full pack
記憶體本機重測 peak RSS 925.8MB
Mac 實測teacher-ref 平均 1.15s/句；平均像度 0.924
手機預估約 2-6s/句，依手機 CPU/NNAPI 差異很大
聲音狀態目前最像 teacher，優先發展
Main pack: models/sherpa/sherpa-onnx-zipvoice-distill-int8-zh-en-emilia-zh-min
2

Piper step1000 FP32

備線：自蒸餾小模型

小 VITS/Piper student，使用 fast phoneme-id frontend。速度漂亮，但音色還不如 ZipVoice，先保留為自研小模型方向。

模型大小60.4MB
記憶體load 後 417MB；peak 556MB
Mac 實測0.112s / 4.69s audio；0.163s / 6.99s audio
手機預估新手機應可 <1s 產 5-7s 音訊；需實機確認 RSS
聲音狀態速度達標；音色仍需更多 teacher data
Backup package: mobile_package/piper_step1000_fp32
3

Qwen3-TTS 0.6B 4bit MLX

高階 iPhone/Apple Silicon 候選

聽感/相似度在舊 baseline 表現好，但 0.6B 4bit 仍是 GB 級記憶體，不適合一般手機即時 TTS。

模型大小0.6B 4bit；實際 package 會是數百 MB 到 GB 級
記憶體GB 級，需高階裝置
Mac 實測舊 baseline 平均約 3.1s/句
手機預估高階 iPhone 可能可跑；中低階 Android 不建議
聲音狀態接近 teacher，但 runtime 太重
4

Piper tiny 300

很小很快，但前端不對齊

14MB 很誘人，RSS 也低一截；但目前 phoneme map 跟 fast frontend 不合，測試時掉了很多音素，不能當正式音色樣本。

模型大小14MB ONNX
記憶體load 後 316MB；peak 337MB
Mac 實測0.018-0.022s；RTF 0.010-0.011
手機預估理論上最快；但要重做 phoneme-id 對齊
聲音狀態目前不可信，只當下一輪小架構方向
5

Piper medium warmstart 100

速度可，但不是主線

大小接近 step1000 FP32，RSS 稍低；同樣出現 phoneme map mismatch，所以不能取代 step1000。

手機預估<1s 可能；但要先修 frontend
聲音狀態不列為目前主包

量化整理

Piper step1000 量化嘗試

壓縮沒有直接成功到可用手機包；目前不要拿失敗的量化模型上 app。

FP3260.4MB，可跑，採用
Dynamic int818.4MB，但 ORT CPU 缺 ConvInteger kernel
MatMul int860.8MB，可跑但沒縮小
FP1631.0MB，但 ORT CPU Reshape error
Static QDQ量化器卡 Softmax calibration bug

結論

現在主線改成 Sherpa-ONNX ZipVoice int8。原因很直接：目前它最像 teacher，而且手機 ONNX 生態成熟。Piper step1000 FP32 保留為自蒸餾小模型備線。下一步不是再比較十個模型，而是把 ZipVoice zh-min pack 丟進 iOS/Android，量實機冷啟動、peak memory、連續合成耗時，並固定一組台灣女生 reference 來做產品聲線。
